# Adversarial review of v3.0.2 (2026-11-06)

**Verdict: approve with reservations. No blocker.** Standard applied: a personal
tool with a public mirror (see `decisions.md`). Reviewed commit: `f623525`
(tag `v3.0.2`). Nothing was changed in the repository during the review; the
actionable findings became GitHub issues on 2026-11-19 and three trivial ones
were fixed the same day.

## Method

Five independent reviewer passes, each given the code but not each other's
conclusions, plus direct checks:

| Pass | Focus | Result |
|---|---|---|
| Runtime | traps, process control, SSH mux, port leases, ADB probe, device parsing | no Major; 6 Minor |
| Security | injection, remote quoting, SSH config parsing, temp files, network exposure, kill guards | 1 Major (shared with docs), 9 Minor |
| Documentation | every README/help/changelog statement against the code | 3 Major, 11 Minor |
| Tests | coverage map, mutation spot-checks, build and CI integrity | 2 Major, 13 Minor |
| Onboarding probe | a fresh agent planning a feature from the docs alone | 4 documentation gaps |

Direct checks: every commit replayed with rebuild and all suites; suites run
under environment variations; shellcheck 0.11.0; both README install
recipes and the release-pinned URL executed; all URLs fetched. Reviewers
reproduced runtime behaviour with fake `ssh`, `adb` and `scrcpy` programs on
`PATH`; no real host or phone was contacted.

**Not covered:** `src/transport.sh` was never exercised against a real `sshd`
or phone. The integration fixture (needs root and `sshd`) and a real-host
test were declined. Transport correctness rests on code review and shim
reproduction.

## Findings

### Major

1. **Completion and parser disagree when `REMOTE_SCRCPY_HOST` is exported.**
   Completion switches to serial completion as soon as the environment host
   exists (`src/completion.sh`, the `explicit_host || REMOTE_SCRCPY_HOST`
   block); the parser assigns the first positional to the host whenever no
   `--host` flag was given (`src/cli.sh`, positional branch). A tab-completed
   serial is then used as an SSH destination. Confirmed by two reviewers.
   → [issue #2](https://github.com/SEPANDESTAN/remote-scrcpy/issues/2)
2. **Sanitized strings republished.** The 3.0.2 changelog entry, the v3.0.2
   release notes and issue #1 quoted the pre-sanitization example alias,
   device serial and OEM model. → fixed 2026-11-19.
3. **README install Option 2 failed without `~/.local/bin`.** `install -m 755`
   does not create the parent directory. Reproduced. → fixed 2026-11-19
   (`install -D`).
4. **`src/transport.sh` has zero automated coverage.** Four planted transport
   mutations, the device-state filter, the scrcpy-argument guard and a
   dropped build module all pass every suite and CI.
   → [issue #3](https://github.com/SEPANDESTAN/remote-scrcpy/issues/3)
5. **Suites inherit `REMOTE_SCRCPY_*` and can open a real SSH connection.**
   With a host exported, the maintenance suite's completion check runs
   `ssh` to it; three of four suites fail. `REMOTE_SCRCPY_COLOR=always`
   fails one check. → [issue #4](https://github.com/SEPANDESTAN/remote-scrcpy/issues/4)

### Minor

- Runtime (tostop stall, SIGHUP forwarded raw, refused forward channel
  triggers remote start-server, no fallback for a vanished control socket,
  `(no serial number)` row mis-split, module-list guard, cleanup comment)

- Documentation (help understates `--` rejections, undocumented `--list` and
  `--requirements`, "ADB server mismatch" wording, `ADB_PORT` in an error,
  utilities list, `/dev/tcp` and `/tmp` notes, timeout clamp, exit codes,
  `--completion=bash`, module header "4.3+", generic fallback variables)
  → [issue #7](https://github.com/SEPANDESTAN/remote-scrcpy/issues/7)
- Security hardening (completion `ssh` without `-n`, UTF-8 C1 controls pass
  the sanitizer, Tab unbounded without `timeout`, quadratic tokenizer,
  loopback exposure undocumented, `COMPLETE_DEVICES` exact `0`,
  `command -v` on exported functions, unexpanded tilde in `COMP_WORDS[0]`)
  → [issue #8](https://github.com/SEPANDESTAN/remote-scrcpy/issues/8)
- `--help` on scripts and doc comments on test helpers
  → [issue #5](https://github.com/SEPANDESTAN/remote-scrcpy/issues/5)
- Repository: inconsistent executable bits across test scripts (one 755,
  three 644; all documented invocations use `bash …`), `actions/checkout@v4`
  tag-pinned rather than SHA-pinned, no repository topics, local clones lack
  the `v3.0.2` tag until `git fetch --tags`.

## Verified correct

Each of these was checked against the code or reproduced with shims:

- Precedence CLI > environment > default; `--` pass-through with the managed
  options rejected before any connection; completion offers only `device`
  state; offline/unauthorized rows shown but not selectable; `r` refreshes
  and `q` cancels; `--list-hosts` needs no SSH, `--list-devices` no GUI;
  listing stdout is data only; completion never prompts.
- Never terminates a shared remote ADB server (one double-fault edge, issue
  #6 item 3); the protocol check prevents restarting a mismatched server;
  cleanup is installed before SSH opens.
- Hosts validated (non-empty, not `-*`, no whitespace or control characters)
  and always placed after `--`; serials never enter a shell string; the only
  remote shell strings are built by `_quote-remote-shell-argument`, which held
  under `dash` and `bash` against every metacharacter tried; SSH config
  parsing executes nothing (`Match exec`, `Include $(…)`, backticks all
  inert); temp directory is 0700 and `rm -rf` is reachable only with a
  directory the launcher created; local forwards bind `127.0.0.1` explicitly;
  remote `adb start-server` with `tcp:PORT` binds loopback (adb `-a` is the
  only way to listen on all interfaces).
- Kill guards: `SESSION_SCRCPY_PROCESS_ID` comes only from `$!`; every group
  kill is gated by `kill -0`; `set -m` gives scrcpy its own process group
  (verified with and without a tty); escalation INT → 5 s → TERM → 2 s →
  KILL measured; exit codes 2/127/130/143/129 and scrcpy's own status all
  produced.
- Bash floor: 4.4 is the true minimum (empty arrays under `set -u`); the
  guard is the first executable statement of the bundle; no 5.x feature used.
- Every documented `REMOTE_SCRCPY_*` variable is read and every read one is
  documented; internal naming table matches the globals; concatenation order
  matches `src/build.sh`.

## Onboarding probe

A fresh agent asked to plan a `--dry-run` option from the docs alone oriented
itself in about ten tool calls and rated the README's maintainer sections as
good. It had to reconstruct from code or git history: the touch points for
adding an option, the release recipe (version in four places including a
test assertion), the fact that CI diffs the committed bundle and that two
suites run the bundle while two source `src/`, and how to run the integration
suite. Those four items are now `AGENTS.md`, the skills under
`.agents/skills/`, `testing.md` and `release.md`.
